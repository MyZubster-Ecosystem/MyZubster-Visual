# MyZubster Cyberpunk Series: From Visual Storytelling to Verifiable Digital Artifacts

MyZubster is evolving as more than an application or a collection of repositories. The goal is to build an ecosystem where software, AI agents, robotics, IoT, real-world activity, digital artifacts and community contributions can be connected through verifiable infrastructure.

The **MyZubster Cyberpunk Series** is the narrative layer of that experiment.

These images are not treated as disposable illustrations. Each canonical visual is stored in GitHub, versioned with the repository, linked to machine-readable metadata and registered with a SHA-256 fingerprint.

> **Real World → Story → Artifact → Metadata → Verification → Bounty → Ecosystem**

## Why GitHub is part of the story

The complete collection lives here:

https://github.com/MyZubster-Ecosystem/MyZubster-Visual/tree/main/assets/cyberpunk-series

Instead of publishing an image somewhere and losing track of its origin, each artifact can live inside a version-controlled repository.

```text
Concept
  ↓
Visual
  ↓
Canonical file
  ↓
Metadata
  ↓
SHA-256
  ↓
Git commit
  ↓
Public artifact
```

Git gives the visual layer a history that developers and automated systems can inspect.

## Machine-readable metadata

The collection has a JSON manifest:

https://github.com/MyZubster-Ecosystem/MyZubster-Visual/blob/main/metadata/cyberpunk-series/manifest.json

A simplified record looks like this:

```json
{
  "asset_id": "MYZ-CYBER-004",
  "filename": "MyZubster-Cyberpunk-Serie-03-Robot-Riciclo-Invenzioni.png",
  "category": "cyberpunk-series",
  "mime_type": "image/png",
  "repository_path": "assets/cyberpunk-series/MyZubster-Cyberpunk-Serie-03-Robot-Riciclo-Invenzioni.png",
  "status": "published",
  "metadata_ready": true
}
```

A human can browse the images. A bot can read the manifest. An API can index it. A marketplace or bounty system can reference an asset by ID.

**The visual is content. The manifest turns the content into structured data.**

## SHA-256 verification

Each artifact receives a SHA-256 fingerprint. The checksum inventory is public:

https://github.com/MyZubster-Ecosystem/MyZubster-Visual/blob/main/metadata/cyberpunk-series/sha256.txt

A verifier can download an artifact and calculate:

```bash
sha256sum artifact.png
```

If the digest matches the registered value, the bytes match the canonical version.

A hash verifies file integrity. It does **not** automatically prove copyright, authorship, truthfulness or entitlement to a reward. Those require separate evidence and policy.

## From comic panels to MYZ bounties

The wider goal is to connect visual storytelling with contribution workflows.

```text
Contributor
   ↓
Discovery / Task / Bounty
   ↓
Story or artifact
   ↓
Metadata
   ↓
Verification
   ↓
Repository history
   ↓
Approval
   ↓
MYZ reward record
```

The same model can later apply to software contributions, documentation, robotics designs, datasets, 3D models, IoT experiments, research and real-world discoveries.

The important rule is simple:

**UPLOAD ≠ PAYMENT**

A file appearing in the repository is not enough to trigger a reward. Verification, approval and settlement remain separate steps.

## The comic phase starts here

The six visuals above are becoming the foundation for an episodic MyZubster comic series.

The next phase will expand them into individual chapters with:

- a canonical visual;
- story context;
- real-world or technical references where appropriate;
- asset metadata and SHA-256;
- GitHub provenance;
- optional bounty references;
- a DEV build/story post for each episode.

The objective is to let the fictional universe grow from the same infrastructure used to document the real project.
